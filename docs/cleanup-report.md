references to `.dev-logs/backend.log` remain valid because `npm run dev`
recreates that directory.

## 5. Risks avoided

- **Did not delete the local database, uploads or evaluation data.** The audit
  identified them as user/runtime state.
- **Did not move existing scripts.** Root `scripts/` and `backend/scripts/` are
  referenced by `package.json`, the README and CI; moving them would break
  verified commands for cosmetic reasons.
- **Did not delete ignored test fixtures.** `backend/testdata/` is large but is
  local evidence and re-downloadable; it is not committed.
- **Did not rewrite Git history or create commits.** The single existing commit
  and all uncommitted work are preserved for the owner.
- **Did not remove the tracked WebM files.** They pre-date this task; the
  restriction was on recording new demo videos, not on deleting existing
  evidence.
- **Did not force the repository into a new directory layout.** The current
  backend/frontend/database/scripts split is already sensible.

## 6. Items requiring owner review

1. **Untracked application source.** Most current features are not in the Git
   index (see `docs/repository-audit.md` §12). Only the owner should decide the
   commit grouping and commit.
2. **`docs/HeritageGraph-AI.pdf`** is an earlier report. If it will be submitted
   as the project report, regenerate it from the current application.
3. **Existing `screenshots/*.webm`** were recorded before the map/story work.
   They remain valid evidence of the analysis flow but not of the latest UI.
4. **`backend/testdata/`** can be removed locally after evaluation if disk space
   matters; it is not needed to run tests or the app.
5. **Credential rotation.** No credential was found in tracked files, but any key
   that has been shared outside this machine should be rotated with its provider.
